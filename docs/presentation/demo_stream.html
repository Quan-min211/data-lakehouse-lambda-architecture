🔀 Auto-Correcting Query Merger — 3 Case phân luồng truy vấn

Khi người dùng truy vấn khoảng thời gian [T_start, T_end], Serving Layer đọc mốc System Watermark W (thời điểm Batch Layer chốt sổ lần cuối) rồi tự động chọn 1 trong 3 trường hợp:

CASE 1 History — 100% Batch View (Ground Truth)
Khi toàn bộ khoảng truy vấn nằm trước Watermark: T_end ≤ W.
→ Lấy 100% từ lakehouse.batch_agg — dữ liệu chuẩn, đã dedup, đã lọc DQ.
→ Nhãn: Reconciled ✓
CASE 2 Realtime — 100% Speed View (Approximate)
Khi toàn bộ khoảng truy vấn nằm sau Watermark: T_start > W.
→ Lấy 100% từ lakehouse.speed_agg — dữ liệu gần đúng, chưa qua Batch reprocess.
→ Nhãn: Provisional ⏳
CASE 3 Hybrid — Batch + Speed, Zero Double-Counting
Khi khoảng truy vấn cắt ngang Watermark: T_start ≤ W < T_end.
→ Phần [T_start, W] lấy từ batch_agg (chuẩn).
→ Phần (W, T_end] lấy từ speed_agg (tức thời).
→ Merge không trùng lặp tại mốc W.
→ Nhãn: Partially Reconciled 🔀
